# x_reply_guy

X Draft Desk is a single-page black web app for watching X accounts, writing reply/commentary drafts, and automatically tracking a daily reply goal.

## Run on your Mac

Requires Python 3.11+. No Python packages to install. Video context also requires FFmpeg/ffprobe (on macOS, use `brew install ffmpeg`).

1. Double-click `Start Draft Desk.command` (or run `python3 app.py`).
2. Open http://127.0.0.1:8765. Click **API keys** in the footer, paste your own **X bearer token** and **OpenAI API key**, then click **Save API keys**. Links in the form take you to each provider's key page. No `.env` editing is needed. Each person runs their own copy and pays for their own API usage.
3. For remote access, double-click `Start Ngrok.command` (or run `python3 tunnel.py`). Ngrok must be installed and configured with your account.
4. Open the HTTPS URL printed by the tunnel. Sign in with the credentials in `data/ngrok-login.txt`. The same login protects localhost while the tunnel is active. Keep this file private.

Keep both processes running and your Mac awake. Ctrl+C stops each process. Monitoring preferences survive restarts. Restarting the tunnel can change its URL; its login stays the same. The tunnel uses app-level Basic authentication over HTTPS, exact Host/Origin checks and CSRF protection. API keys and drafts are never served as files. Ngrok request inspection is disabled. Do not expose the server through another tunnel or port-forwarding configuration.

## Use

- The top bar holds your watchlist. Click **+**, search an exact **@username**, confirm the profile photo/name/bio, then **Watch**. Search also offers a link to the full X profile. Photos fall back to initials if unavailable. Up to 20 accounts are supported. This does not follow them on X.
- When you add an account, monitoring first fetches its latest existing original post, then checks new posts. Existing watched accounts receive the same one-time latest-post lookup on upgrade. Replies/reposts are excluded. The empty inbox says **Monitoring posts…** while monitoring is healthy.
- Review and edit **Reply** or **Your take**, then open the X composer to publish yourself. Replies aim for one short, conversational reaction (usually 5–18 words), with an actual opinion or angle rather than a summary of the source. Context analysis stays behind the scenes. Your custom writing voice still applies. Commentary includes the source URL. Add your own X username under **Your daily reply goal**. The app detects replies sent on X and automatically removes their direct source posts from the queue. **Replied & archived** shows completed posts, with a link to detected replies. **Mark replied manually** remains a fallback; manual marks can be undone and do not increase your reply count. Saving or regenerating a draft does not undo completion. Archive other finished drafts. No sample posts appear in the interface.
- Use the angle buttons above the draft to rewrite **both Reply and Your take**: **Agreeable** supports the point with something useful, **Disagree** challenges a claim, **Controversial** offers a defensible minority view, and **Provocative** makes a sharp observation. **Auto** chooses a stance from the context. The selected angle is saved per post and reused by **Regenerate both**. Each rewrite uses one AI draft attempt and can read context again. Successful rewrites replace both drafts; failed or skipped attempts keep the previous text and angle. The model receives the previous drafts to avoid simply repeating them. All angles must stay grounded in the source; selecting a stronger tone does not guarantee a useful counterargument.
- Open settings with **API keys** in the footer. Saved keys remain hidden; leaving a field blank keeps its saved value. Keys live in an owner-readable `.env` on the computer running this copy and are excluded from Git. Environment variables override them at startup. Saved credentials are verified when their provider is first used. This is a single-user app: sharing its hosted login shares that copy's settings, keys and usage, rather than creating a separate account.

## Automatic replies and daily progress

Open **API keys** → **Your daily reply goal**, enter your own X username, and save. The default goal is **23 replies**; you can change it. Turn on monitoring in the footer. Each copy tracks one selected account with its own X API access.

The app reads your account's posts about every 60 seconds (the configured interval), including replies sent outside this app. Its first scan starts at midnight of the current London day. Later scans resume from a saved cursor and catch up through pagination; restarting does not double-count posts. Matching uses the direct replied-to post ID, so quoting a post or replying elsewhere in its conversation does not mark it done. Existing draft text is preserved. Replies detected before a watched post enters the inbox are matched when it arrives.

The footer shows **replies / daily goal** and your pace. Click it for total posts, original/quote posts, replies remaining, expected progress, the average replies per hour needed by midnight, and the last successful check. All replies count, including replies to accounts outside the watchlist. Reposts do not count. Counts reset at **00:00 Europe/London** and include morning replies before 10:00. Counts reflect posts observed by the app; later deletions are not subtracted. X visibility, timeline retention, indexing delay and available API credits can limit detection.

Click the bell and **Allow** browser notifications. Nudges are eligible only **10:00–00:00 London time**, when your detected reply count is behind an even pace toward the daily goal. Existing 26/27-minute checkpoints limit nudge frequency; they are opportunities to check progress, not a quota of notifications. Reaching 23 replies (or your chosen goal) silences nudges for that day, even if you finish early. No separate “I've posted” acknowledgement is needed.

Counts and completion continue updating while the server is running and monitoring is enabled. Nudges require the page to stay open, permission for that browser/URL and the Mac to stay awake; background tabs and Focus settings may delay delivery. There is no closed-page push. Incomplete scans, API errors or stale tracking pause nudges and show the problem. A server-side claim rechecks progress and prevents duplicate notifications across tabs. Only a checkpoint within five minutes is eligible; missed nudges are not replayed. Pausing nudges keeps tracking active; pausing monitoring also pauses activity checks.

## Costs and limits

Polling defaults to 60 seconds per account; rate limits, pagination and AI generation can add delay. API access/billing are separate. New installations default to 500 possible post reads and 40 AI draft attempts per UTC day; existing settings are preserved. Each AI attempt generates both drafts. Failed/uncertain reads retain reserved slots conservatively. Your activity scan shares the daily read allowance with watched accounts. Expanded reply/quote references also count as reads; each activity page reserves up to four post reads per result before requesting it, then releases unused slots after a valid response. Account lookups are separate X charges. These safeguards are not dollar spending caps; use provider billing limits.

Draft generation sends source text, quoted/referenced posts, downloaded X images, timestamped video frames, audio transcripts, and readable linked-page excerpts to OpenAI with response storage disabled. Photos and video frames are passed as actual vision inputs. Spoken audio is sent separately to OpenAI’s `gpt-transcribe` transcription API; successful transcripts are cached locally by audio content so regeneration avoids another transcription charge. Additional post lookups count toward the read allowance; image/frame inputs, audio transcription and longer context can increase AI charges. Audio attempts have a separate daily limit equal to the configured daily draft allowance, displayed in settings; failed attempts still count. Failed drafts await manual retry. The inbox shows the newest 300 posts; older records remain in SQLite. Timeline cursors and duplicate prevention persist. Long offline gaps are subject to X retention/access limits. Review facts and attribution before publishing. Each draft reads up to four source/referenced posts, eight photos, two native X videos/GIFs and three public HTML/text pages (12,000 characters per page). Long-post text is included when X supplies it. For each native X video/GIF, it downloads an MP4 of at most 80 MB and five minutes, samples up to 24 timestamped frames across the full clip, and transcribes its full audio track when present. Clips exceeding these limits are flagged, not silently truncated. Sampling can miss rapid action; transcripts can mishear speech and do not capture tone or non-speech sounds reliably. The model is instructed to skip if those missing details are essential. Temporary media files are deleted after analysis. External video sites, live streams and unavailable MP4 variants need manual review. It does not read PDFs, log into websites, or bypass paywalls; it does not promise the whole thread. Missing source or direct-reference context stops new AI drafting and retains any existing draft for manual editing. Limits or failures on older quoted background are shown as warnings; drafting can proceed from the context actually read unless the missing detail is essential. Combined image and video-frame inputs are limited to 32 million encoded characters. Empty drafts show the specific pause, failure, skip or queue reason. Unreadable images or page challenges should be skipped by the model. The context note shows what was supplied and what is missing. Edit/save manually after checking the source, or retry generation. Media decoding disables network access and external track references. Public-page fetching blocks private network addresses, pins validated DNS addresses, validates redirects, and sends no app credentials or browser cookies. Publication and following remain manual.

## Verification

```sh
python3 -m unittest -v
node --test test_frontend.cjs
node --check static/app.js
```

Tests cover timeline recovery, usage allowances, draft failures, secret handling, authenticated tunnel access, CSRF/Origin checks, reply matching, activity pagination/restarts, daily goal suppression, stale-data handling, London midnight/DST, duplicate claims, account lookup caching and edit preservation. Tests use temporary databases and mocked provider calls. Desktop/mobile empty layouts, account-search interaction and reply-progress display were checked. A live activity scan detected seven replies and matched them to their inbox posts. Public tunnel access was checked for unauthenticated rejection and authenticated success. Actual OS notification delivery and publishing in X have not been verified.
